# خطة تنفيذ: تحسين تجربة المعلم والطالب

## نقطة البداية والقيود

- أساس العمل: فرع `fix/launch-blockers-rc` عند `d163208` داخل worktree مستقل؛ لا تُلمس تعديلات الشجرة الأصلية.
- `main` ليس فرع الإصدار الحالي. PR #27 إلى `release/launch-2026-11-rc` ما زال جارياً، ويجب مراجعة CI قبل دمج أي تغيير.
- الإنتاج وواجهة الصحة متاحان، لكن لا يوجد Deploy SHA/Release مسجل يمكن مطابقته مع الموقع، ولا يوجد نشر تلقائي عند الدمج.
- لا تغيير للأسعار أو الدفع أو صلاحيات الوصول أو سياسات Bunny، ولا ترحيل قاعدة بيانات دون حاجة مثبتة.

## مراحل التنفيذ

1. **التنقل المشترك:** اختبار ثم تحسين شريط الطالب («المزيد» والوجهات اليومية والشارات الحقيقية)، وإضافة وصول المعلم للرسائل والبحث في التنقل؛ إبقاء كل الروابط والبوابات حسب الصلاحيات.
2. **مهام المعلم:** استخدام ملخص خفيف قائم على بيانات موجودة أو استعلامات تجميعية محدودة للاختبارات والواجبات والحجوزات؛ إظهار الإجراءات التي يستطيع المستخدم تنفيذها فقط.
3. **تعلمي:** فصل فشل التحميل عن حالة «لا توجد كورسات»، إبراز متابعة كورس بتقدم محفوظ، وتقليل بروز رمز التسجيل دون إزالة طريق الوصول إليه.
4. **منشئ الكورس:** تنظيم الواجهة الحالية بمسار خطوات وإجراءات مراجعة/نشر صريحة، مع إبقاء المحررات والروابط الحالية والحفظ والمسودات ورفع Bunny كما هي.
5. **الإعدادات:** تجميع التبويبات الحالية تحت أقسام أوضح، مع حفظ جميع الإعدادات والبوابات الحالية.
6. **النماذج والحالات:** استبدال `prompt`/`confirm` في التدفقات المستهدفة بحوارات متاحة، ورسائل خطأ محلية، وإعادة محاولة آمنة.
7. **الجودة:** اختبارات وحدات/تكامل/بناء، فحص RTL والهاتف في المتصفح إن ظلت أداة المتصفح متاحة، ومراجعة أمنية وأدائية للـdiff.

## نقاط التحقق

- بعد كل شريحة: اختبارات مركزة ثم مراجعة diff.
- قبل PR: مجموعة الاختبارات الكاملة المتاحة، TypeScript، Build، فحوص Laravel وE2E.
- لا دمج أو نشر إذا بقيت CI حمراء/معلّقة، أو تطلب النشر تغيير بيانات/إعدادات إنتاج خارج بوابات المستودع.

## مخاطر

| الخطر | المعالجة |

| فقدان مسودات محرر الكورس أو تغيير مساراته | الإبقاء على المحررات الحالية، وإضافة تنظيم تدريجي واختبارات مسار |
